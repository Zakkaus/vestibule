# 本机器人保存哪些个人相关数据

**本软件会保存其不拥有的群组中的成员数据。** 运行本软件副本的人员持有用户记录，而记录所涉用户未曾与其直接达成任何约定。
这些用户只是加入 Telegram 群组，群组管理员将机器人添加至其中。

本文首先说明这一事实。

**不存在唯一的官方实例。** 本项目为开源项目，任何人均可运行实例。
具体实例的运营者持有相应数据，决定保存期限并承担相关责任。
本文说明**软件本身**的行为，该行为在每个副本中均相同；**具体实例**的行为由其运营者决定，第 4 节供其说明。

## 1. 读取的数据

- **入群申请。** 群组启用加入审批后，Telegram 会将申请发送给机器人，其中包含申请人的用户 ID、用户名和显示名。
- **成员变更。** 成员加入、离开、被提升为管理员或被限制。
- **机器人担任管理员的群组中的消息。** Telegram 会为管理员身份的机器人关闭隐私模式，因此机器人会接收这些群组中的全部消息。消息用于反垃圾信息和自动回复功能，**不保存消息正文**。
- **发送给机器人的私聊消息。** 申请人通过私聊回答挑战题目。验证完成后，私聊中的题目和结果**不会自动删除**，它们是申请人了解处理经过的记录。群组中的挑战消息会被删除，因为该消息会公开显示某人正被拦截。

## 2. 保存的数据

下表所列数据表均来自已检查的数据库结构迁移。
`scripts/check-privacy-tables.py` 会检查所有迁移；如果数据库结构新增含用户或群组标识符的数据表而本文未列出，检查将失败。

| 数据表 | 关联对象 | 保存内容 |
|---|---|---|
| `chat` | 群组，而非个人 | 群组 ID、标题和设置 |
| `challenge` | 申请人 | 用户 ID、群组 ID、最终状态及原因、尝试次数、时间戳、执行结算的管理员，以及 `payload`：题目、选项、**挑战发出时的显示名**和投递挑战时使用的消息 ID |
| `verification_failure` | 申请人 | 用户 ID、群组 ID、失败次数、最近一次失败时间 |
| `warning_counter` | 群组成员 | 用户 ID、群组 ID、当前警告数 |
| `rule` | 不直接关联个人 | 某个群组的题目、回复和过滤规则；管理员若在其中写入姓名，则可能包含个人信息 |
| `pending_action` | 申请人或群组成员 | 机器人针对某次挑战即将执行但尚未完成的操作：操作内容、重试次数及上一次错误。它不直接记录用户 ID，而是关联到一条 `challenge`；该记录的 ID 形式为 `chat:user:nonce`，其中包含两个标识符 |
| `verification_observation` | 成员关系变更关联申请人或群组成员；其他操作不关联任何可识别个人 | 被抑制的操作及其时间。批准、拒绝、封禁、解封、禁言和解除禁言的记录还保存群组 ID 和用户 ID。不保存消息正文、通知正文、callback ID 或其答案、挑战答案以及 Telegram 消息 ID |

以下三张表不保存个人数据：`agent_tally` 统计挑战中 AI 诱捕触发时自报的模型名称；
`verification_runtime` 保存两个数值；`update_poll_lease` 记录当前从 Telegram 读取更新的进程。

**本软件不保存**：消息正文、电话号码、电子邮件地址、IP 地址、位置信息，以及 Telegram 未随上述事件发送的任何字段。本软件不会读取其不担任管理员的群组消息，也无法读取 Telegram 的秘密聊天消息。

## 3. 保存期限

- **挑战记录**会在结算后保留，作为管理员了解处理经过及撤销误判的操作记录。
- **失败计数**构成冷却期，并随冷却期到期而失效。
- **警告**会保留至被清除，或因计数达到上限而被移除。
- 机器人被移出群组，或管理员从控制台删除群组数据时，该群组的记录会被删除。
- **只观察模式下的成员关系变更记录**会随相应群组的数据一并删除。
  无标识符的操作和时间记录会继续保留，用于切换前后的比较。

实例可以采用更短的保存期限；如需延长保存期限，必须修改代码。

## 4. 实例运营者必须决定并说明的事项

请将本节复制到您的实例页面并完整填写。留空本身也是一种答复，但并非适当的答复。

- **实例运营者及其联系方式。**
- **数据库的位置：**所在机器及其国家。
- **可访问控制台且因而可查看上述记录的人员。**
- **日志保存期限。** 日志与数据库相互独立，详见第 5 节。
- **是否与他人共享数据。** 软件本身不会共享数据，但实例运营者可以共享。
- **请求删除个人记录的方式及所需时间。**

## 5. 日志

机器人会写入操作日志。日志包含**用户 ID 和用户名**，例如一条日志可为 `join 8913270020 (@someone) in group -100…`，并会记录当时的判定及其依据。日志不包含消息正文或挑战答案。

日志的存储位置、可访问人员及保存期限由实例运营者决定，并须在第 4 节中说明。
通过 systemd 安装时，日志写入 journal，并遵循该机器的保留策略。

## 6. 群组成员

相关方通常有两类，且通常并非同一批人员：

- **所在群组的管理员**选择使用此机器人并设定题目，也可查看和撤销机器人对该群组作出的判定。
- **实例运营者**负责运营该程序并持有数据库。

请先联系群组管理员；管理员可通过控制台删除您在该群组的记录。
如需进一步信息，群组管理员可告知实例运营者的身份。

## 7. 实例运营者

实例运营者持有这些数据。本软件提供以下工具，使运营者能够如实说明这一事实：

- 从控制台删除某个群组的数据会将其清除，界面会说明所需时间。
- 将机器人移出该群组具有相同效果。
- 第 2 节所列内容均可核查；对应的 SQL 架构可逐行查看。

本文不构成法律意见，也不会使您的实例符合任何法规。
本文仅明确说明实例运营者持有的数据；任何如实说明均应以此为起点。
