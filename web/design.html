vestibule · 控制台

不用品牌色的控制台

默认界面不使用品牌色相。灰阶承担层次，状态色只出现在第 01 节枚举的位置。 品牌标记与强调色选择器展示的是内容色样，不表示状态。

00

定位

这是一台控制台。使用者是当班的管理员，进来做三件事：改配置、查清一次判定的来龙去脉、 处置正在等待的申请。所有取值服从一句话，这句话可以证伪：

改动的可追溯性优先于操作的便捷性。

后面每一节都拿它对照。「点一下就生效、不留痕迹」的开关违反它，这不是风格问题。 配置影响的是九百人的群，改错一个开关的代价不是重画一屏。

首页的顺序由任务决定

首页不按视觉重量排序。四层及其顺序由第 06 节统一规定； 此处只给判断依据：先识别变化和待办，再进入配置。

不做双套界面

受众只有运维者一类，不分简单版和专业版。拥有者和群管理员的差别是 服务端授权边界，界面只表达权限，不表达模式。

非状态颜色的两个例外

品牌标记自带颜色，因为它是内容，不是界面状态。 颜色只限标记本身，周围的组件不跟随变化。

另一个例外是第 15 节的强调色选择器。 色样只展示候选值；启用后的强调色仍只进入该节列出的四个位置。

深色不是反色

底色到面的层次要看得出三级：background 0.06 → card 0.125 → popover 0.165。 早先那版 0.07 → 0.13 → 0.14 三级挤在一起，卡片浮不起来。 边框同时调深调锐，让卡片边缘在更亮的卡片填充上仍然读得出。

形状与层次

组件 CSS 的圆角由一个种子推导，不写字面量。--radius: 0.625rem， 其余四档由 calc() 乘系数得出。Lucide 图标与图表 SVG 的固定几何不属于组件圆角。 控制台停在这个尺度：再大像消费级应用，再小像终端。

面的分层

层次靠底色变化，不靠投影堆叠。投影只做三件事：用 --shadow-card 给卡片一道极淡的边，用 --shadow-lift 抬起悬停面与对话框， 用 --shadow-btn 反馈按钮悬停。卡片内的嵌套面用 --raised，不加边框。

04

首次部署

装的人未必懂 Telegram 的机器人体系，也未必想读文档。 脚本负责机器上的事，网页负责配置：令牌、身份、第一个群都在浏览器里填， 不在命令行里问。

这样分还有一个好处：令牌不进命令行历史， 也不会因为终端回滚被人看到。

打不开的时候看到什么

这个产品没有登录屏。群管理员从 Telegram 里打开，身份来自每次请求携带的 签名数据；运维打开机器人发的一次性链接，链接换成会话。两条路都没有表单， 也没有密码，因此没有「输入账号密码」这一屏。

但有人会在没有有效会话时打开这个地址：链接过期了、链接已经用过、 在浏览器里直接访问、或者换了个账号。这时看到什么必须定下来， 否则每一种都会落到同一个白屏或同一句「未授权」。

情况屏上说什么为什么这么说
直接访问，没有会话 说明这个控制台从哪里进：群管理员在 Telegram 里打开机器人的菜单， 运维向机器人要一条链接。给出机器人的用户名 大多数人到这里是走错了地方，需要的是方向而不是错误
链接过期 「这条链接已过期」，并说明去哪里再要一条。 不要只说「无效」：过期和伪造要分开，前者是常事 一次性链接有寿命，过期是设计的一部分，不是异常
链接已被用过 与过期分开说。已用过意味着可能有别人先点了， 这一句要写出来，让人有机会警觉 同样是「不能用」，但一个是时间到了，一个可能是有人抢先
会话有效，但这个人不管任何群 不是错误。说明他的账号没有被任何群授权，并给出他的数字 ID， 好让群主把他加上 身份对了、授权没有，这是两回事，界面上不能混成一句
Mini App 之外打开，而他是群管理员 说明群管理员这一面只在 Telegram 内可用，并给出在桌面版打开的路径 这是刻意的取舍，代价要当场讲清楚，不是让人以为坏了

五种都不要求人重试。每一种都给出下一步该做什么， 而不是一个刷新按钮。重试对其中任何一种都不起作用。

这一屏与首次部署的引导是同一套外壳： 居中一列、不带侧栏、不带群切换器 —— 因为此刻还没有群可以切。

脚本在机器上做什么

装的人这一步只需要粘一条命令。脚本不问任何密钥， 它问的每一件事都有默认值，一路回车能走完。

安装流程重跑同一条命令是升级，不是重装
1 取下来先验签 校验通过才执行，不校验就等于让人随便换掉内容 2 认这台机器 发行版、进程管理器、有没有容器运行时、端口占没占 3 问四件事 全部有默认值，见下表 4 装好并起服务 建数据目录、写单元文件、起进程、等它健康 5 打印一个链接 剩下的在浏览器里做
问什么默认直接回车会怎样
装成容器还是系统服务容器 没找到容器运行时才会问要不要顺带装一个，不问就装是越权； 不装就退回系统服务。两条路装完的样子一样，更新按钮都在
域名不填 不填就只监听本机，页面上给出用端口转发打开控制台的那一条命令。 不把控制台默认暴露到公网
控制台地址随机端口加随机路径 不落在人人都知道的地址上，挡掉按固定端口批量扫描的那一类。 因此装完必须把完整地址给全，人记不住默认值
证书有域名时自动申请 没有域名也能拿到浏览器认的证书，走面向公网地址的短期证书， 续期任务当场装好。装完打印的是一条可以直接打开的完整地址， 不让人自己拼
目录按 Linux 惯例 配置在 /etc/vestibule，数据在 /var/lib/vestibule， 日志交给进程管理器。可以整体换到别处，换了之后升级和卸载认同一套路径

脚本一个密钥都不问。 机器人令牌、自建接口的凭据、绑定的身份，全部在浏览器里填。 命令行历史会被别人翻到，终端回滚会把它显示出来， 而这两件事装的人都不会想到。

先解决一个绕不过去的问题

首次打开时还没有机器人，拿什么证明打开网页的人就是装它的人？ 上一代已经解决过：脚本生成一个短期一次性口令， 部署者把它私聊发给机器人，机器人据此绑定他的 Telegram 账号。 有效期十分钟，用过即失效。

这条链的顺序不能换，因为每一步都依赖上一步的产物：

步骤操作为什么在这里做
1打开控制台脚本打印一次性链接，点开即认领这台控制台
2填机器人令牌立刻显示机器人名字，确认令牌没有粘错

每一步先说要做什么，再做

步骤失败时说什么
认领控制台 链接过期就再执行一次脚本的某个子命令重新生成，写清是哪个子命令， 不要只说「链接无效」
填令牌 令牌不对说「这个令牌没被接受」，连不上说「连不上 Telegram」。 两者分开：一个要重填，一个要查网络
绑定账号 口令过期就当场再给一个。收不到消息时提示先给机器人发一条任意消息， 因为机器人无法主动私聊没有交互过的人
拉进群 权限不足时逐项列出缺哪个，并说明缺了会导致什么， 不是只说「权限不足」

装完不是空的

走完四步直接可用：验证已开、反垃圾的四条默认规则已开且处于只记录档、 文案是默认的。不需要再配十几项才能用。

最后一屏给两个按钮：先看看首页，或者装一个配置包。 需要 Linux 社区那套的人点后者，不需要的人直接走。

装完之后按什么顺序配

引导走完就能用，但真正开始用之前还有几件事。把它们排成一条明确的顺序， 而不是丢一个有二十项的设置页让人自己找。首页顶部留一条进度， 三件必做的没做完就一直在，做完自动消失。

顺序做什么为什么排在这
必做确认这个群用哪种验证方式 出厂给的是一种通用默认。群的性质决定该用哪种： 技术群可以出题，商业群通常只该做人机校验
必做把反垃圾从只记录改成真拦截 出厂是只记录不拦截，先让人看几天自己群里会命中什么， 确认没有误伤再打开。不看就开会误删正常发言
必做再加一个管理员 只有一个人能进控制台，这个人换手机就没人能进了
可选改文案 默认文案能用。留空即用默认，改过的会标出来，随时能还原
可选装配置包 题库、自动回复、订阅源、要开哪些模块，一次装好一整套。 Linux 社区那套是其中一个包，不是内置行为
可选接第二个群 一个机器人管很多群。每个群的配置各自独立， 也可以指定从已有的群整体复制过去

每一项都能之后再改，没有一次性的选择。 装的时候选错验证方式不会变成必须重装，这一条直接影响人敢不敢往下点。

引导只走一次。之后重新打开进的是首页， 但这四步在诊断屏里保留为一份检查清单：权限、令牌、绑定、群， 出问题时按同样的顺序排查。

一行一项。项名写它做什么，不写它是什么。改过默认值的项带一个琥珀点， 作用域徽标写清是全局还是本群。

保存

默认不做即时保存，改动先累积，由一条保存条汇总并写明改动数量； 可选的即时模式及其撤销约束见第 15 节。默认取值来自定位原则： 保存条同时提供反悔窗口和一次可记录的改动单元。

提交时只发送改动过的字段。整份配置回写会覆盖其他管理员在同一时间的修改， 而群内通常不止一名管理员。同一字段发生冲突时提示对方的取值，由人决定，不自动合并。

每一项还须标出当前取值的来源。来源与「本次未保存」是两件事， 分开显示：来源说明这个值是谁定的，未保存说明它还没生效。

当前项的四重标记

侧栏的「首页」同时改了四样：字重加粗、左侧一条 3px 短轨、 图标描边由 2 加到 2.4、底色换为 --accent。 四样中没有一样是色相，因为没有品牌色可用， 并且在屏幕切换为灰度显示后仍可分辨。

只有等待队列带待办计数，因为只有它表示需要处理的事项； 侧栏中的版本号是对象标识，不是待办计数。统计与诊断由使用者主动查看，不挂数字。 导航计数用于催办，不用于陈述；数量过多则失去提示作用。

首页分四层

顺序固定：先看情况有没有变化，再看哪些需要处理，然后看趋势，最后才是改配置。

同一个机器人在两种群里的行为不一样，这是群的属性，不是可以改的设定项： 审批制下未通过的人在群外，先入群后限制下他已经在群里、只是不能发言。 两者对「没通过会发生什么」的答案完全不同，因此群列表每一行与首页顶部 都要显示当前是哪一种，不能只在某个二级页面里提一句。

验证方式

验证方式是两条独立的轴。把它们混成一个下拉框是现在这版的问题： 内核版本号被写死成一种模式，加第二种就得改代码。

投递渠道

挑战出现在哪里。群内、私聊、网页，可以同时开。 网页不是只能放工作量证明：题库里的填空题和选择题一样能在网页上答， 有些人更愿意点一下而不是在群里打字。网页链接一次性，带签名和有效期。

挑战类型

要对方做什么。下面六种，可以串几个，全过才放行。 外部条件要看它命中之后做什么。 「必须已关注某频道」是挑战：申请人要去做一件事再回来， 一样有待验证记录与到期时间，只是判定依据在 Telegram 那边，不在答案里。 「已在主群就免验证」不是挑战：它在任何挑战之前求值，命中即整串跳过， 不产生记录，也没有到期时间。同一种条件类型，两种用法要分清。

内核版本号只是一个模板

现在这道题是写死的代码：正则、可能的版本范围、以及题面里那个占位符， 全在 Go 里。它应该退回成题库里的一条，用和别人自己加的题完全一样的形式表达。 下面是它存下来的样子，人看到的是再下面那个编辑器，不是这段文本。

存下来是这个样子不是让人手写
- id: kernel-version
  type: rule
  delivery: [dm, group, web]
  input: text
  prompt:
    zh-Hans: 你正在用的 Linux 内核版本号是多少
    en: What kernel version are you running
  accept:              # 全部满足才算过
    - version_range: { min: 2.6, max: 6.99, normalize: strip_suffix }
  reject:              # 命中任意一条即失败
    - one_of: ["X.Y.Z"]    # 题面里给的占位符，原样发回即失败
  escape: no-linux      # 给没在用 Linux 的人一条出路

否决的是题面自己给出的那个占位符，值得单独说，因为很容易写反。 题面示例写的是 X.Y.Z，并明说不要发送示例中的占位符； 把它原样发回来的人即判失败，而真在用 Linux 的人念的是 uname -r 的输出。 任何人加自己的题时都能用 reject 做同样的事。

不要改成否决某个具体版本号。本书早先的版本写的是 one_of: ["7.1.30"]，理由是「这个版本不存在」。 上一代生产代码里有一条测试恰恰相反 —— internal/verify/kernel_test.go:59 写着 a real future kernel line must never be blacklisted， 并另有一条断言真实的 7.1.30 应当立即通过。 按写反的那版实现，7.1.30 发布那天就会开始拒真人。 占位符不会有这个问题：没有哪台机器的 uname -r 会输出 X.Y.Z。

编辑器实现

富文本编辑器通常建模成一棵文档树，而 Telegram 的实体是一段纯文本上的扁平区间： 从第几个字符起、多长、什么样式，允许互相重叠。两种模型不相容， 硬套树形编辑器要在两边来回转换，而转换最容易引入缺陷。

参考里有这件事的代价：一个同类项目为了在实体与树之间转换， 写了六个文件一千一百余行，其中专门定义了按 UTF-16 码元索引的字符串类型， 还要防实体越界。它必须这么做，因为它的目标格式是树。我们的不是。

做法代价
可编辑区域加文档树 输入法、撤销、选区都要自己处理，还要在树与扁平区间之间双向转换。 这是富文本编辑器最难的部分，且难点不在我们要解决的问题上
纯文本输入框加实时预览 不是原地所见即所得，格式效果显示在下方。 换来的是发送路径零转换：编辑器产出实体，平台直接接收实体

取后者。文本、输入法、撤销、选区全部交给浏览器原生的输入框； 工具栏只做一件事：给当前选区追加一条实体；下方预览按文本加实体渲染， 与发出去的完全一致。

  • 偏移按 UTF-16 码元算。与平台一致。 按字节或按字符算，中文和表情会错位，而错位的实体不报错，只是把样式套在别的字上。
  • 删改文本时同步移动实体。在选区之前插入字符，后面所有实体整体后移； 删掉的区间被实体覆盖时按重叠部分裁剪。
  • 预览就是验收。不另做「发送预览」， 因为两份渲染迟早不一致，而不一致的那一次没人会发现。

这套同时用于自动回复、题面、进出提示与文案定制。 一个编辑器，四处使用；它们的差别只是可用的占位符不同。

链接预览是三态，不是开关

链接按钮最多两行，每行最多三个

护栏

自动回复容易成为噪音来源，因此以下限制不提供开关：

  • 一条消息最多触发一条规则。按顺序匹配，第一条命中就停。 否则单条消息可同时触发多条回复，短时间内刷屏。
  • 冷却。同一条规则在同一个群里，一段时间内只回一次。 默认十分钟，可调整。成员刷屏时机器人不随之重复发送。
  • 不回机器人。两个启用自动回复的机器人相遇时， 缺少该限制会形成无限互相回复。
  • 正则有上限。长度有上限，执行有超时。 写法不当的正则会耗尽 CPU。这是公开服务，单个群不应影响整机。
  • 条数有上限。按群限制，超出时拒绝并说明超出项。

  • 首次订阅不补推历史。第一次抓取只记录当前条目，不发送任何消息。 这是订阅功能上线首日最常见的故障： 一个含五百条历史的源会在瞬间刷满整个群。
  • 连续失败后暂停并通知。源不可用时停止重试， 在本屏标出状态并通知管理员，而不是每半小时静默失败一次。

按群限制源数量与抓取频率。这是公开服务， 单个群订阅一百个源会占满抓取队列，代价由其他群承担。

一个 bot，很多群

这是一个公开的机器人，谁都可以拉进自己的群，拉进去就是他自己的机器人， 他自己配。我们社区不是特别版，只是其中一套设定。

把我们社区那几行配置删掉，产品要照常运转。

这句话是可以验的，而且它管着代码：if 是主群 then 这种分支一条都不能有。 我们那几个群在库里就是几行数据，和别人的群走同一份代码、同一套出厂默认值、 同一个界面。

没有全局默认这回事

今天的配置模型是「全局默认加每群覆盖」。这在只服务我们自己时成立， 在这里不成立。所谓全局默认，本质上就是把我们的偏好写成了所有人的起点。 模型要改成出厂默认加每群取值，出厂默认对谁都一样，谁也改不了别人的。

身份不用我们做

一个人能不能配某个群，答案完全在 Telegram 手里：他是不是那个群的群主或管理员。 因此没有注册、没有用户表、没有邀请码。登录只是取得其 Telegram 数字 ID， 每次写入前重新查询他当前是否仍为管理员。被撤销管理员权限的人在下一次操作时即被拒绝。

租户列表也是同样来的：机器人在哪些群里，这个人在哪些群是管理员，取交集。 不保存租户表，因为保存的副本迟早与 Telegram 不一致。

小程序的安全边界

群管理员这一面只能从 Telegram 内打开，这确实移除了一大块攻击面： 没有公开登录页可供爆破，没有密码库可泄露，没有注册与找回密码流程。 但它解决的是身份认证，没有解决授权与令牌保管。

运维那一面不同：他要看诊断、版本、证书，而这些恰恰在出事时才看， 那时 Telegram 可能正好不通。所以运维走机器人发的一次性链接， 在普通浏览器里换成会话，整条链不依赖 Telegram 的登录服务。 两个面都没有密码。

代价说清楚：群管理员不能在普通浏览器里打开控制台。 桌面版 Telegram 里可以，这对绝大多数人够用；不够用的那些人， 真正要的通常是运维那一面。

默认不做的，以及在哪打开

下面这些是默认取值，不是禁令。默认带着观点，因为不带观点的默认等于没有默认； 但这个机器人别人也要部署，别人的社区有别人的样子。开关全在 /preferences，打开之后仍然受一条约束管着，写在最右边。

项默认打开之后
强调色 无。纯灰阶 可以给一个品牌色相。只允许出现在主按钮、当前导航项、链接、焦点环四处， 四个语义色相的地盘一处都不让。存之前跑对比度检查，两个主题都过 4.5:1 才让存
站点标记 随二进制发的那张标记，加控制台名字 可以换成自己的。顶栏高度不变，超出按高度缩放； 两个主题都要读得清，做不到就深浅各给一张；必须带替代文本， 因为它同时是返回首屏的链接
标题图标 关。图标只出现在它本身承担识别功能的地方 可以给章节标题配图标。同一屏要么都有要么都没有，不允许一半有一半没有
保存方式 保存条。改动攒着一起提交 可以改成即时保存。改成之后操作记录仍然逐项记，撤销窗口从「放弃」变成 记录里的撤销，两者必须有一个在
首屏 首页。四层及顺序见第 06 节 可换成其他屏。换后等待队列须位于导航第一组，不得移入二级
动效 只做即时反馈：按下、悬停 可以加更多。全部服从 prefers-reduced-motion，这条不给开关

约束不是装饰。打开强调色之后，那四处以外还出现品牌色，就是这一节没写清楚， 或者代码没照着做，两者都要修。

偏好屏实例

站点标记 顶栏左上角那张，同时是返回首屏的链接。换掉之后替代文本要一起改。 两个主题都要读得清，做不到就深浅各传一张。
深色版标记 可选 留空就两个主题共用上面那张。
控制台名字 全局 标记右边那行字，也是浏览器标签上的名字。
强调色 默认无 选了之后只出现在主按钮、当前导航项、链接和焦点环这四处。 存之前跑对比度检查，两个主题都过 4.5:1 才让存。
标题图标 默认关 开了之后同一屏的标题要么都有图标，要么都没有，不允许一半一半。
保存方式 改成即时保存之后，撤销窗口从「放弃」变成操作记录里的撤销。

这一屏自己也走保存条，改外观和改机器人配置是同一套提交方式。 标记更换后写入操作记录，因为它对所有访问者可见。

不给开关的三条

这三条不是偏好，是代码规则。给开关的意思是允许两种写法同时存在， 而它们的代价正好是「两种写法同时存在」本身。

  • 组件规则里不写主题分支。深浅两套只重新声明 token，状态色也一样。 出现 [data-theme] .some-component 就是 token 层缺了一个名字， 补名字，不是补分支。给这条开关等于允许一半组件走 token、一半走分支， 换主题时必然有一半跟不上。
  • 组件规则里的颜色只从 token 取。token 块之外不写界面颜色字面量； 本节的候选色样是展示数据，不参与组件样式。这是上一条能成立的前提。
  • 线上不运行 Node。前端构建产物 go:embed 进二进制。 这条关系到部署是一份还是两份，不是外观。

关于「通用后台的样子」

大圆角卡片、彩色渐变、图标装饰与首屏大数字组合在一起，即为常见的通用后台外观。 默认取值避开这一组合，因为它初次观感良好，长期使用则妨碍操作。 本节只开放表中的六项偏好，不把这套组合另做一个总开关。

Vestibule 控制台设计语言。取值继承自同作者生产项目的 token 层， 改样式前先看这里，新页面照这里取值。
